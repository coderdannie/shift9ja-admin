Admin Dashboard Integration Guide

Helper Category Distribution

Integration manual for frontend and product engineers detailing helper metrics distribution across task categories and geographical regions.

1. Business Context & API Design

To optimize helper acquisition and task dispatching campaigns, administrators need to analyze the current distribution of Active Helpers grouped by their Primary Task Category and location (State and City).

The backend exposes a highly optimized aggregation endpoint that compiles database metrics, caches the result for 30 minutes to safeguard database resources, and formats it cleanly for data grids and chart modules.

💡

Response Metrics Summary

This endpoint filters for users who hold the "helper" role, have an "ACTIVE" profile status, and evaluates their locations based on their active geolocations table mapping.

API Endpoint Specification

Method Endpoint Headers
GET /admin/dashboard/user-category-distribution Authorization: Bearer <JWT>

Caching Architecture

  • Cache Strategy: Managed by NestJS CacheInterceptor.
  • Cache Key: admin_user_category_distribution.
  • TTL (Time-To-Live): 1800 seconds (30 minutes). Avoid rapid page-reloads requesting this raw from the database. Let the UI rely on local memory state or trigger manual refresh bypasses only when necessary.

2. Interface Design Recommendations

Visualizing multi-dimensional data (Category x State x City x Helper Count) requires clear structures to prevent dashboard noise. We recommend implementing the following modules in the Admin View:

Visual Hierarchy & Layout Flow

  • KPI Summary Grid (Top Row): Show summary widgets including Total Active Helpers, Primary Hotspots (State), and Most Active Helper Specialty. This updates in real-time based on filters.
  • Geographical Filter Panel: A sticky filter bar allowing admins to narrow down the dataset by State, City, or Category before examining details.
  • Dynamic Bar Chart (Middle): Render a horizontal bar chart showing the helper counts per category. A horizontal format handles long category names without overlapping labels.
  • Interactive Heatmap Matrix: An optional visualization grid displaying categories as rows and cities as columns. The cells should change opacity/color based on helper density.
  • Paginated Data Grid (Bottom): A high-performance table containing search indexing, column sorting (click header to sort userCount descending), and export controls (CSV/Excel).
⚠️

Design Gotcha: "Unknown" Locations

When the query returns state: "Unknown" or city: "Unknown", style these rows with muted labels to indicate missing profile configurations. Do not filter them out, as these helpers still contribute to the total counts.

Theme Tokens & Colors

Integrate this module using Shift9ja's Admin Theme colors:

  • Background Cards: #121824 (Secondary card background)
  • Data Highlights: Indigo-to-Purple gradients (linear-gradient(135deg, #6366f1, #8b5cf6))
  • State Labels: Use standard badge colors (Emerald green for active metrics, Amber for warning indicators).
