Frontend Integration Guide

Detailed guide for front-end developers integrating the real-time Administrative Notification system using REST endpoints and Socket.io WebSockets.

1. Architecture Overview

The Admin Notification system ensures that administrators are immediately alerted when critical activities occur across the platform (such as SOS triggers, geofence deviations, support tickets, and disputes). It leverages a dual-layer stack:

  • REST API Endpoints: Used to load paginated history tables, manage individual notifications, and mark alerts as read/read-all.
  • WebSockets (Socket.io Gateway): Delivers low-latency real-time messages directly to open browser sessions, enabling desktop toasts and active badge counters.

2. Authentication

All endpoints and WebSocket connections are restricted to authorized administrators. You must pass the Admin JWT Token generated during login:

🔒

REST Requests: Include the token in the Authorization header using the Bearer scheme:

Authorization: Bearer <admin_jwt_token>

3. WebSocket Integration

Real-time notifications are broadcasted through a Socket.io gateway under the /notifications namespace.

Connection Details

Establish a connection pointing to the notifications namespace. Authentication credentials must be provided as a token within the socket handshake:

typescript 
import { io } from 'socket.io-client';

// Connect to the namespace
const socket = io('https://api.shift9ja.com/notifications', {
  auth: {
    token: '<YOUR_ADMIN_JWT_TOKEN>'
  },
  transports: ['websocket']
});

Rooms & Scoping

Upon connection validation, the backend places the admin socket connection into specific groups automatically:

  • admin & admins: For global broadcasts targeting all administrators.
  • admin_<admin_id>: For direct alerts aimed exclusively at that specific administrator (e.g. admin_5).

Listening to Events

Register a listener on the admin_notification event. This event triggers whenever a new persistent admin notification is created.

JSON (admin_notification Payload Example) 
{
  "uuid": "d66a9d70-349f-4318-b2ef-001a1c97a2df",

4. REST API Reference

Endpoints are versioned under /v1/admin/notifications.

A. Fetch Paginated Notifications

Fetches historical admin notifications. Automatically resolves whether the viewing admin has already read each alert.

Request: GET /v1/admin/notifications

Query Param Type Required Default Description
page Number No 1 Active pagination page
limit Number No 10 Items returned per page (Max: 100)
type String No - Filters list to specific category (e.g. SOS_ALERT)
isRead Boolean No - Filter by read status (true / false)
Response (200 OK) 
{
  "success": true,
  "message": "Admin notifications retrieved successfully",
  "data": {
    "items": [
      {
        "uuid": "d66a9d70-349f-4318-b2ef-001a1c97a2df",
        "title": "Critical Location Deviation",
        "body": "Helper John Doe has moved 150m...",
        "type": "DEVIATION_ALERT",
        "data": { "taskId": 128 },
        "createdAt": "2026-06-23T09:45:10.820Z",
        "isRead": false
      }
    ],
    "meta": {
      "totalItems": 1,
      "itemCount": 1,
      "itemsPerPage": 10,
      "totalPages": 1,
      "currentPage": 1
    }
  }
}

B. Mark Specific Notification as Read

Flags a single notification as read by the viewing administrator.

Request: PATCH /v1/admin/notifications/:uuid/read

URL Parameter: uuid (The notification's string identifier)

Response (200 OK) 
{
  "success": true,
  "message": "Admin notification marked as read successfully",
  "data": null
}

C. Mark All Notifications as Read

Marks all unread notifications visible to the logged-in administrator as read.

Request: PATCH /v1/admin/notifications/read-all

Response (200 OK) 
{
  "success": true,
  "message": "All admin notifications marked as read successfully",
  "data": null
}

5. Reference Enums & TypeScript Interfaces

Include these definitions inside your project model schemas:

typescript 
export enum AdminNotificationType {
  SOS_ALERT = 'SOS_ALERT',
  DEVIATION_ALERT = 'DEVIATION_ALERT',
  NEW_DISPUTE = 'NEW_DISPUTE',
  NEW_SUPPORT_CHAT = 'NEW_SUPPORT_CHAT',
  SYSTEM_ALERT = 'SYSTEM_ALERT',
  LARGE_TRANSACTION = 'LARGE_TRANSACTION',
}

export interface AdminNotification {
  uuid: string;
  title: string;
  body: string;
  type: AdminNotificationType;
  data?: Record<string, any>;
  isRead: boolean;
  createdAt: string;
}

export interface PaginatedResponse<T> {
  success: boolean;
  message: string;
  data: {
    items: T[];
    meta: {
      totalItems: number;
      itemCount: number;
      itemsPerPage: number;
      totalPages: number;
      currentPage: number;
    };
  };
}

6. React Integration Example

Here is a basic custom React Hook utilizing socket.io-client to connect and listen to live admin-bound alerts:

typescript (useAdminNotifications.ts) 
import { useEffect, useState } from 'react';
import { io, Socket } from 'socket.io-client';
import { AdminNotification } from './types';

export function useAdminNotifications(token: string, backendUrl: string) {
  const [socket, setSocket] = useState<Socket | null>(null);
  const [liveAlerts, setLiveAlerts] = useState<AdminNotification[]>([]);

  useEffect(() => {
    if (!token) return;

    // Connect pointing to the /notifications namespace
    const socketInstance = io(`${backendUrl}/notifications`, {
      auth: { token },
      transports: ['websocket'],
    });

    socketInstance.on('connect', () => {
      console.log('Connected to admin notifications gateway');
    });

    // Listen for live admin alerts
    socketInstance.on('admin_notification', (notification: AdminNotification) => {
      setLiveAlerts((prev) => [notification, ...prev]);
      
      // Hook toast alerts or window chime notifications here
      console.log('Real-time admin alert:', notification.title);
    });

    socketInstance.on('disconnect', () => {
      console.log('Disconnected from notifications gateway');
    });

    setSocket(socketInstance);

    return () => {
      socketInstance.disconnect();
    };
  }, [token, backendUrl]);

  return { socket, liveAlerts, setLiveAlerts };
}
